# Portfolio Analytics Dashboard

เว็บแยกสำหรับดูประวัติการเข้าชม Portfolio โดย source code อยู่ใน repository เดียวกับเว็บพอร์ต แต่ deploy เป็น Cloudflare Worker คนละ URL

## สิ่งที่ระบบเก็บ

- เวลาเริ่มเข้าชมและเวลาที่เห็นล่าสุด
- เวลาออกโดยประมาณและระยะเวลาที่อยู่บนเว็บ
- URL path โดยตัด query/hash, เว็บไซต์ต้นทางเฉพาะ origin, ภาษา, timezone, ขนาดหน้าจอ
- Browser, ระบบปฏิบัติการ และ Desktop/Mobile/Tablet โดยประมาณจาก User Agent
- ประเทศ เมือง จังหวัด/ภูมิภาค และรหัสภูมิภาคจาก `request.cf` เท่าที่มี ไม่เก็บ IP, พิกัด, รหัสไปรษณีย์ หรืออ้างว่าเป็นที่อยู่จริง/เขตที่แน่นอน
- ใช้รหัสสุ่ม first-party ใน localStorage อายุ 180 วันสำหรับผู้ชมที่กลับมา ไม่ใช้ fingerprint และไม่เชื่อมข้อมูลข้ามเว็บไซต์ คนละเบราว์เซอร์/ล้างข้อมูล/โหมดส่วนตัวอาจนับใหม่
- ไม่เก็บชื่อ อีเมล ข้อมูลในฟอร์ม หรือข้อความที่พิมพ์ เคารพ `Do Not Track` และ `Global Privacy Control` ผู้ชมปิดสถิติได้ในท้ายเว็บ
- การเปิดแต่ละหน้าและการดูส่วนของหน้า (hero/about/echo-glove/achievements/contact) พร้อมเวลาใช้งานเมื่อแท็บมองเห็นและมีการใช้งานใน 60 วินาทีล่าสุด
- การเปิดผลงาน/โปสเตอร์และรูปใน gallery, คลิกลิงก์/ปุ่ม, ระดับการเลื่อน 25/50/75/100% วัดต่อการเปิดหน้า ไม่นับซ้ำเมื่อเลื่อนขึ้นลง

การเปิดเอกสารใหม่/รีเฟรช = 1 session; รหัสผู้ชมเดิมทำให้แยกการกลับมาได้ เวลาใน session เป็นเวลาตั้งแต่เข้าเว็บ ส่วนเวลาอ่านของหน้า/ส่วน/ผลงานนับเฉพาะการใช้งาน ไม่ควรบวกเวลาหน้าเว็บรวมกับเวลาส่วน/ผลงานเพราะช่วงเวลาซ้อนกันได้

เมื่อเปิดผลงาน modal จะหยุดเวลาอ่านของส่วนที่อยู่ด้านหลัง การส่งข้อมูลเป็น best effort: บราวเซอร์บล็อกสคริปต์/อินเทอร์เน็ตหลุด/ปิดแอปทันทีอาจทำให้ข้อมูลบางส่วนหายได้ แหล่งที่มาไม่มี referrer แสดง “โดยตรง / ไม่ทราบ” ไม่รับรองว่าเปิดเองเสมอไป

ข้อมูลก่อนอัปเดตยังอยู่ แต่การคลิก/การเลื่อน/เมืองและรหัสผู้ชมไม่สามารถสร้างย้อนหลังได้ Dashboard แสดง 200 sessions ล่าสุด, เนื้อหา 100 กลุ่ม และลำดับเหตุการณ์ 500 รายการแรกต่อ session; สรุปคำนวณจากข้อมูลทั้งหมดในช่วงที่เลือก

## อัปเกรดฐานข้อมูลเดิม

Worker สร้างตาราง `analytics_*` เพิ่มแบบ idempotent ผ่าน D1 batch ซึ่งเป็น transaction เมื่อ API ถูกเรียกครั้งแรก เก็บตาราง sessions เดิมไว้ จึงใช้กับฐานข้อมูลที่สร้างผ่าน Console ได้โดยไม่ต้อง ALTER หรือรัน migration เดิมซ้ำ ตารางเพิ่มเติมอยู่ใน `src/schema.js` การทดสอบตรวจการอัปเกรดจาก schema 0001 และข้อมูลเก่าไว้ด้วย

## แจ้งเตือนเข้ามือถือ (Web Push)

1. เปิด Dashboard ผ่าน Chrome บน Android แล้วเข้าสู่ระบบ
2. กด “รับแจ้งเตือนบนเครื่องนี้” และอนุญาตการแจ้งเตือน (สิทธิ์นี้ขอจากเจ้าของ Dashboard เท่านั้น)
3. กด “ส่งทดสอบ” แล้วตรวจแถบแจ้งเตือน จากนั้นลองเข้าพอร์ตจากอีกแท็บ/อีกเครื่อง

Worker ส่ง Web Push เมื่อพบ session ใหม่ผ่าน `ctx.waitUntil` โดยไม่ต้องเปิด Dashboard ค้างไว้ ใช้ Service Worker แสดงแจ้งเตือนและเปิดรายละเอียด session เมื่อแตะ ข้อความบนหน้าจอล็อกไม่มีรายละเอียดผู้ชม ความเร็วขึ้นกับระบบ Push, เครือข่าย และการตั้งค่าแบตเตอรี่/แจ้งเตือนของ Android ไม่รับประกันเวลาถึงเครื่อง

สร้าง VAPID key pair บน Worker โดยอัตโนมัติหลังเจ้าของกดเปิดใช้งาน เก็บเฉพาะ public key ที่ client; private key ใน D1 เข้ารหัส AES-GCM ด้วย key ที่ derive จาก ADMIN_TOKEN ไม่ใช้รหัสจริงใน repository หรือ local file เปลี่ยน ADMIN_TOKEN แล้วต้องเปิดรับแจ้งเตือนใหม่ทุกเครื่อง กุญแจ/การสมัครเดิมจะถูกแทนที่เมื่อเปิดใช้อีกครั้ง

รับได้สูงสุด 10 เครื่อง; กดปิดแจ้งเตือนหรือออกจากระบบจะยกเลิกเครื่องนั้น endpoint ที่หมดอายุ (404/410) ถูกนำออกอัตโนมัติ ป้องกันส่งซ้ำด้วย session ID และลองใหม่หลัง 60 วินาทีเมื่อส่งล้มเหลว ไม่มีค่าบริการ Push เพิ่ม และยังใช้โควตา Workers/D1 ของแผนปัจจุบัน ไม่มีการอัปเกรดแผนหรือเปิด paid service

Service Worker ไม่ cache Dashboard/API/token จึงไม่เปิดข้อมูลส่วนตัวแบบ offline และใช้ `_headers` จำกัด script/connect origin

## Deploy ครั้งแรก

ต้องมี Node.js และ Cloudflare account ที่เปิด Workers/D1

1. เข้าโฟลเดอร์นี้แล้วติดตั้ง dependency: `npm install`
2. Login: `npx wrangler login`
3. สร้างฐานข้อมูล: `npx wrangler d1 create portfolio-analytics`
4. นำ `database_id` ที่ได้ไปแทน `REPLACE_WITH_D1_DATABASE_ID` ใน `wrangler.jsonc`
5. ตั้ง origin ของเว็บพอร์ตใน `ALLOWED_ORIGINS` เช่น `https://supanat-dev.github.io` หากมีหลาย origin ให้คั่นด้วย comma
6. สร้าง Admin Token ที่ยาวและสุ่ม แล้วบันทึกเป็น secret: `npx wrangler secret put ADMIN_TOKEN`
7. รัน migration: `npm run db:migrate:remote`
8. Deploy: `npm run deploy`
9. นำ URL ที่ได้ไปใส่ใน `data-analytics-endpoint` ของ `index.html` ที่ root

จากนั้น deploy เว็บพอร์ตอีกครั้ง Tracker จึงเริ่มบันทึกข้อมูล

## ทดสอบในเครื่อง

ใช้ Node.js 22 ขึ้นไป; รัน `npm test` เพื่อทดสอบ Worker/SQL จริงด้วย SQLite, tracker, การนับซ้ำ, วันตามกรุงเทพฯ และ Web Push encryption รวมทั้งการส่ง HTTP ใน workerd/Miniflare runtime เดียวกับ Cloudflare โดยจำลองบริการ Push ไม่ส่งแจ้งเตือนไปบริการจริง ต้องให้ process ทดสอบเชื่อม loopback ในเครื่องได้

การส่ง Push ใช้ `redirect: 'manual'` และปฏิเสธ 3xx โดยไม่ส่งต่อไป URL อื่น เพราะ Workers ไม่รองรับ `redirect: 'error'` ข้อผิดพลาดจากบริการ Push แสดงรหัส/ข้อความแยกจากข้อผิดพลาดฐานข้อมูล และเครื่องที่ subscription หมดอายุสามารถเปิดรับใหม่ได้

1. รัน `npm run db:migrate:local`
2. สร้างไฟล์ `.dev.vars` (ไฟล์นี้ห้าม commit) โดยใส่ `ADMIN_TOKEN=รหัสสำหรับทดสอบ`
3. รัน `npm run dev`
4. ตั้ง `ALLOWED_ORIGINS` ของ local dev เป็น `http://127.0.0.1:8000` (Production ยังคงเป็น GitHub Pages)
5. รัน `node tests/preview-server.mjs` แล้วเปิด `http://127.0.0.1:8000` ซึ่งส่ง analytics ไป Worker ทดสอบที่ port 8787 เท่านั้น

## ความแม่นยำของเวลาออก

Tracker ส่ง heartbeat ทุก 15 วินาทีและส่ง end event ตอนออกจากหน้า หากเบราว์เซอร์ถูกปิดทันทีหรือเน็ตหลุด ระบบจะใช้ heartbeat ล่าสุดและทำเครื่องหมาย `timeout` จึงอาจคลาดเคลื่อนได้ประมาณ 15–45 วินาที
